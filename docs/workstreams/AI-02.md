## 2026-10-03 — Release Gate audit: technical realism + spoiler/abuse

Status: NOT READY for public production. LIVE mysterylogic.com and production Supabase remain unchanged by this audit.

### Spoiler/abuse — FAIL found
- Deployed `ai-interrogation-v2` had drifted ahead of GitHub main: production contained free-form `investigate`, while main did not. This makes the deployed backend non-reproducible from main.
- The deployed free investigation path passed the full hidden evidence map to the text model and then accepted model-selected `evidence_ids` into authoritative session state. A prompt-injection or model failure could therefore unlock hidden evidence outside the intended investigation path.
- AI-02 suspect prompts also received private `base_facts` and full private `persona` at zero stage. For the culprit and several witnesses these fields contain hidden acts. This means early spoiler resistance depended on model compliance instead of server state alone.
- Fix branch: `fix/ai02-release-gate-abuse-20261003`; draft PR #361.
- The branch first synchronizes the actually deployed v6 endpoint/runtime into GitHub, then changes AI-02 free investigation to deterministic server-gated evidence candidates before any LLM wording step, and prevents AI-02 zero-stage prompts from receiving private base_facts/persona. Production deployment has NOT been performed.
- Required before PASS: PR contract CI green; production deploy only with explicit approval; authenticated adversarial E2E against exact deployed build; verify no hidden evidence/culprit/confession leaks before state thresholds; remove temporary test workflow.

### Technical realism — FAIL / canon correction required
- Current E07 treats filesystem creation/last-modified timestamps as proving the recording could not have been made later. NIST guidance says file timestamps can change during copying, depend on clock configuration, and can be altered; timestamp evidence alone is not strong enough for that categorical conclusion. The evidence needs corroboration from an application/session/audit log, immutable ingest record, hash-linked archive record, or equivalent independent source.
- E23/N-SEROV-KNOWLEDGE is currently treated as forbidden knowledge because Sеров mentions the exact pause before the recovered source is shown to him. But E24 simultaneously establishes that Sеров was director/author of the 1998 final edit. That creates a plausible innocent explanation for remembering the edit/source detail. As written, the clue is not exclusive enough to carry the required inference.
- Required canon fix: either establish that the specific phrase/pause exists only in a newly recovered source Sеров could not previously have accessed/remembered, or replace the forbidden-knowledge clue with a detail uniquely tied to the newly discovered copy/current incident. Do not modify private canon in public GitHub.
