# Mystery Logic — Blind Investigator Provider Contract v1

Status: ACTIVE PROTOTYPE
Updated: 2026-09-23

## Purpose

Connect an AI investigator/playtester without exposing Private CANON.

The provider boundary is one-way:

```
PRIVATE CASE DNA
      |
build-blind-packet
      v
BLIND PLAYER PACKET
      |
prompt builder
      v
AI INVESTIGATOR
      |
blind run validator
      v
BLIND RUN
```

The AI provider MUST NOT receive the source Case DNA, canonical hypothesis, reveal, mechanism, supports/weakens labels, evidence reliability labels, intended solve path, confession rules or private author notes.

## Provider input

Only:
- the prompt contract generated by `build-blind-investigator-prompt.mjs`;
- the current `blind_player_packet_v1`.

No retrieval over private canon is allowed in the investigator context.

## Provider output

One stage checkpoint compatible with `blind_run_v1`:
- theories with confidence;
- supporting/contradicting evidence IDs;
- assumptions;
- established facts;
- unresolved questions;
- next action;
- confusion;
- reasoning mode.

The validator rejects any evidence ID that is not present in the player packet.

## Isolation rule

A provider execution is invalid if:
- the same model context was previously shown the private answer;
- hidden Case DNA is attached through retrieval/memory;
- system/developer text includes the culprit or intended solution;
- the provider can query a tool that exposes private canon;
- the response references unavailable evidence.

A deterministic baseline is useful only as an engineering smoke test. It is NOT evidence of mystery quality.

## Future execution

Preferred production architecture:
1. server creates stage packet;
2. stateless investigator context is created;
3. packet is sent to provider;
4. response is validated;
5. only validated blind-run data returns to Case Architect;
6. Case Architect compares the blind path with private CANON after investigator execution is complete.

This boundary is also suitable for future external human blind-test clients.
