# Mystery Logic / «Кто врёт?» — веб-версия

Веб-проект первой игровой линейки экосистемы **Mystery Logic**. Контент синхронизируется с редакционно проверенной мобильной библиотекой, а игровой цикл остаётся общим для всех расследований.

## Текущая контрольная точка

**Web 1.7 — SEO-native pilot.**

Сохраняется текущая продуктовая модель:

- 100 активных дел;
- 15 бесплатных игровых дел;
- 85 закрытых дел полного первого тома;
- единый игровой движок без дублирования логики;
- локальный прогресс без регистрации;
- каталог, профиль следователя, достижения и существующий визуальный стиль.

Поверх работающей версии добавлен ограниченный SEO-native пилот: только три существующих бесплатных дела опубликованы на новых канонических адресах `/ru/cases/{slug}/`. Старые `/delo/{slug}/` для этих трёх дел сохранены как совместимые игровые адреса, но имеют `noindex,follow` и canonical на новый URL.

## Архитектура

### CASE

`tools/import-mobile/load-active.mjs` нормализует каждое активное расследование в единую сущность Case. Помимо исходных игровых данных Case содержит:

- `id`, `title`, `slug`;
- `shortDescription`, `story`;
- `characters`, `statements`;
- данные ответа и объяснения из исходного дела;
- `difficulty`, `category`, `ageGroup`;
- `language`, `status`, `access`, `isFree`;
- `image`;
- `relatedCases`;
- `seoPath`, `legacyPath`, `seoPublished`;
- принадлежность к коллекции.

Для **каждого** Case автоматически рассчитывается постоянный языковой SEO-адрес `/{language}/cases/{slug}/`. На первом этапе публично генерируются только три проверочных SEO-native страницы; остальные маршруты не мигрируют массово.

### COLLECTION

Существующие наборы мобильной библиотеки нормализуются в Collection: `id`, `title`, `description`, `language`, `status`, `caseIds`, `indexable`.

Сейчас `indexable=false`: генератор не создаёт автоматически пустые или слабые страницы подборок. Публичную коллекцию можно включать только после отдельной редакционной подготовки.

### GAME ENGINE

Работающий движок сохранён:

- `ktovret-game/assets/app.js` — безопасный загрузчик;
- `ktovret-game/assets/app-core.js` — игровой цикл;
- `assets/case-adapter.js` — адаптация разных типов дел;
- `tools/import-mobile/witness-postprocess.mjs` — интерфейс отдельных свидетелей и текущие UX-слои.

SEO-переход не требует отдельной копии движка для каждого дела.

### SEO LAYER

`tools/import-mobile/case-pages.mjs` генерирует HTML страниц, а `tools/import-mobile-cases.mjs` — индекс Case/Collection и `sitemap.xml`.

На SEO-native странице до запуска JavaScript уже присутствуют:

- уникальный H1;
- короткое описание;
- завязка/условие дела;
- показания персонажей;
- варианты ответа без раскрытия правильного;
- ссылки на следующее и похожие дела;
- ссылка на библиотеку.

JavaScript затем заменяет этот серверно сгенерированный слой действующим интерактивным интерфейсом. Правильный ответ и полный разбор не публикуются в статическом SEO-слое.

Каждая индексируемая страница получает уникальные `title`, `meta description`, canonical, Open Graph, JSON-LD и hreflang-ready разметку. В sitemap попадают только канонические URL.

## Аналитика

`assets/analytics-events.js` формирует события воронки:

- `case_view`;
- `case_started`;
- `answer_selected`;
- `answer_correct`;
- `answer_wrong`;
- `case_completed`;
- `next_case_clicked`;
- `paywall_viewed`;
- `purchase_started`.

Слой не привязан к одному провайдеру: он пишет в `dataLayer`, вызывает `gtag` при его наличии, может отправлять цели в Яндекс Метрику при заданном `MYSTERYLOGIC_YM_COUNTER` и создаёт DOM-событие `mysterylogic:analytics`.

## Как добавляется новое дело

Источник контента остаётся мобильная библиотека `valera2872/ktovret`. После добавления и публикации нового активного дела импорт автоматически:

1. получает Case из исходного JSON/GZIP-пакета;
2. проверяет уникальный `id` и корректность ответа;
3. формирует стабильный `slug`;
4. рассчитывает `seoPath = ru/cases/{slug}/`;
5. добавляет дело в общий индекс и Collection;
6. подбирает связанные дела.

На пилотном этапе фактическая публикация нового канонического SEO-маршрута отделена от расчёта URL: `seoPublished` включён только для трёх тестовых дел. После проверки индексации и UX этот предохранитель можно распространить на остальные качественные бесплатные дела без изменения Game Engine.

## Проверки

CI перед публикацией проверяет:

- исходную библиотеку 100 / 15 / 85;
- синтаксис всех JS-слоёв;
- все 100 редакторских игровых конверсий;
- сохранение 100 legacy-маршрутов;
- три SEO-native страницы и наличие индексируемого контента до JS;
- canonical/noindex для legacy-дублей;
- sitemap;
- уникальность SEO title пилотных дел;
- наличие всех событий аналитики;
- отсутствие раскрытия решения в статическом SEO-слое.

Массовая SEO-генерация остальных дел и автоматическая индексация Collection специально не включены до проверки пилота.
